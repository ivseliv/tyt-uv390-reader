Программа для чтения и редактирования настроек раций TYT MD‑UV380 и MD‑UV390.

## Ubuntu Desktop 24.04 LTS

Скачайте пакет `.deb` для архитектуры вашей системы. Команда `dpkg --print-architecture` покажет `amd64` (Intel и AMD) или `arm64` (например, Ubuntu в виртуальной машине на Mac с Apple Silicon). В каталоге с загруженным файлом выполните:

```sh
sudo apt install "./tyt-reader_0.7.0-1_$(dpkg --print-architecture).deb"
```

Откройте **TYT Reader** из меню приложений или командой `tyt-reader`. Для просмотра и редактирования файлов рация не нужна. Для работы по USB подключите включённую рацию в обычном режиме. Если кабель уже был подключён во время установки, отсоедините его и подключите снова, чтобы Ubuntu применила правило доступа. В виртуальной машине сначала передайте USB-устройство гостевой Ubuntu. Запускайте саму программу от обычного пользователя.

Интерфейс поддерживает русский, английский и упрощённый китайский. Доступны те же команды чтения, локального редактирования и записи пяти таблиц, что и в Windows.

Для сборки из исходников установите инструменты командой `sudo apt install build-essential dpkg-dev pkg-config libusb-1.0-0-dev` и запустите `bash linux/build-deb.sh` в каталоге проекта. Готовый пакет для архитектуры этой системы появится в `dist/ubuntu/`.

## Запись настроек по USB

1. Подключите одну включённую рацию со штатной прошивкой в обычном режиме. Нажмите **Считать настройки** и внесите правки. Также можно открыть штатный RDT или полный снимок TYT Reader с моделью и DMR ID подключённой рации.
2. Нажмите **Записать в рацию…**. Программа сравнит документ с подключённой рацией и покажет число изменённых записей по таблицам. Для одинаковых данных запись не предлагается.
3. Выберите новое имя для резервной копии `.tytbackup` и подтвердите запись. Держите рацию включённой и подключённой до сообщения об успешной проверке. Перед записью приложение заново сверяет данные, а после читает обратно каждый обновлённый сектор.

Поддерживаются добавление и изменение каналов, контактов DMR, зон A/B, групп приёма 54–250 и списков сканирования. Позиции, которые отсутствуют в документе, сохраняются в рации. DMR ID и группы приёма 1–53 находятся в общем секторе с данными Privacy. Этот сектор, ключи, калибровка и другие разделы CPS исключены из записи. **Сохранить JSON…** и **Сохранить копию RDT…** сохраняют правки на компьютере.

Команда **Сервис → Восстановить настройки из резервной копии…** предлагает отменить изменения, если каждый сектор совпадает с состоянием до записи или после неё. Рация стирает каждый обновляемый сектор целиком. При обрыве питания или связи во время его перезаписи автоматический откат может оказаться невозможен. Функция проверяется на имитаторе USB. Запись на физической MD‑UV390 10 Вт с прошивкой D219.043 ещё не подтверждена. [Реализация программирования TYT в qdmr](https://github.com/hmatuschek/qdmr/blob/v0.15.1/lib/tyt_radio.cc)

## Windows x64

Распакуйте **весь ZIP** в отдельную папку и запустите **TYT Reader.exe**. Приложение открывает JSON TYT Reader, RDT из CPS, YAML qdmr и CSV каналов и контактов. **Файл → Сохранить JSON…** сохраняет локальную копию. **Сервис** открывает редакторы DTMF, файлов Privacy и калибровки. Язык переключается в меню **Язык / Language / 语言**.

**Считать настройки** читает рацию по USB. Для этого Windows должна предоставить интерфейс программирования драйверу, совместимому с libusb, например WinUSB. Для открытия файлов драйвер не требуется. Установка приложения не меняет драйверы Windows. [Поддерживаемые драйверы Windows в документации libusb](https://github.com/libusb/libusb/wiki/Windows#driver-installation)

Из исходников интерфейс запускается командой `py -3.12 windows_app.py` в каталоге проекта (64-битный Python с Tk). Переносимый комплект с USB-помощником собирается на Windows командой `.\windows\build.ps1` в PowerShell. Нужны Visual Studio 2022 Build Tools с инструментами C++, 7‑Zip и 64-битный Python 3.12. Скрипт собирает приложение, запускает тесты и сохраняет результат в `dist/windows-x64/TYT-Reader-Windows-x64.zip`.

## TYT Reader для macOS

Распакуйте ZIP для macOS и откройте `TYT Reader.app`. При сборке из исходников приложение появится в каталоге `dist/`. Для работы с файлами кабель не нужен.

Язык интерфейса выбирается в меню **Язык / Language / 语言**. Доступны **Русский**, **English**, **简体中文** и системный язык macOS. После выбора завершите приложение (⌘Q) и откройте его снова. Имена из кодплага сохраняются в исходном виде.

| Действие | Как выполнить |
| --- | --- |
| Открыть настройки | **Открыть файл…** (`⌘O`). Подходят штатные RDT MD‑UV380/390 размером 852 533 байта, YAML qdmr, снимки JSON и CSV каналов или контактов. |
| Посмотреть параметры | Выберите раздел слева. В разделе **Каналы** выделите строку для просмотра субтонов, назначения контакта, группы и дополнительных параметров. Слева доступны также меню, кнопки, SMS, VFO, GPS, сигнализация и таймеры. Набор данных зависит от источника. |
| Изменить настройки | **Редактировать копию…** (`⌘E`). В пяти основных таблицах доступны добавление, дублирование и удаление. Для зон, групп и сканирования кнопка **Выбрать…** открывает список участников с поиском и изменением порядка. Дополнительные разделы позволяют редактировать настройки рации, SMS, назначение кнопок, VFO, GPS и профили тревоги. |
| Взять за основу другой файл | В меню **Файл → Новый из шаблона RDT…** выберите собственный штатный кодплаг. Черновик наследует его настройки и связи. **Файл → Новый кодплаг…** открывает пустой документ для JSON. |
| Добавить таблицу | В редакторе **Импорт CSV…** обновляет записи по номерам. Вне редактора **Открыть файл…** открывает CSV как отдельный документ. |
| Сохранить правки | В редакторе нажмите **Сохранить копию RDT…** и выберите новое имя. Для USB, JSON и совместимого YAML кнопка **RDT по шаблону…** переносит в копию выбранного штатного RDT основной DMR ID и основные поля пяти таблиц. Остальные настройки берутся из шаблона. **Сохранить JSON…** сохраняет снимок поддерживаемых настроек для любого источника. |
| Экспорт и печать | Меню рядом с кнопкой редактирования содержит экспорт каналов и контактов в CSV, экспорт основных таблиц в YAML qdmr и **Печать…** (`⌘P`). Полный снимок USB или RDT позволяет сохранить таблицу каналов в 51 колонке Windows CPS, контакты — в четырёх. Для неполных данных доступен формат CSV Reader. В системном окне печати есть предпросмотр и сохранение PDF. |
| Считать рацию | Подключите одну включённую рацию и нажмите **Считать настройки**. Изменения в редакторе относятся к локальному документу. |

Программа проверяет ссылки и читает созданный RDT обратно перед публикацией копии. Неизвестные байты исходного RDT сохраняются. Удаление используемого канала или контакта требует исправить его назначения в черновике. JSON содержит распознанные поля. Если в старом снимке TYT обнаружатся группы с недопустимыми номерами контактов, их позиции будут перечислены в разделе «Группы приёма». При переносе такого снимка на шаблон соответствующие группы берутся из шаблона.

Состав экранов, таймкоды и подтверждённые отличия версий приведены в [справочнике по CPS](CPS-REFERENCES.md). Возможности чтения и редактирования каждого раздела перечислены в [таблице совместимости](CPS-COVERAGE.md).

### Меню «Сервис»

| Команда | Как пользоваться |
| --- | --- |
| **Последовательности DTMF…** | Выберите систему, одну из 32 строк передачи либо обычный декодер. Введите до 30 символов из 0–9, A–D, * и #. Для RDT выберите **Сохранить копию RDT…**. Команду можно открыть без кодплага или из сохранённого USB-снимка. При переносе только DTMF остальные таблицы берутся из выбранного RDT. |
| **Basic и Enhanced (USB)…** | Нажмите **Считать настройки** и откройте команду в разделе **Privacy** или меню **Сервис**. Выберите Basic или раскладку Enhanced, затем позицию и **Показать значение**. Ключи доступны в текущем сеансе просмотра. В сохранённый JSON входят назначения Privacy каналам. |
| **Считать Universal Privacy по USB…** | В меню **Сервис** откройте таблицу слотов. Штатный сеанс чтения завершается перезагрузкой рации. В столбце **Ответ USB** нули или FF означают, что наличие ключа определить не удалось. Фильтр **Слоты 1–4** показывает всю первую четвёрку. **Сохранить отчёт…** записывает в новый JSON модель рации и сведения о видимых слотах (номер, имя, тип и статус). Исходное значение можно посмотреть отдельно в собственном DEC, сохранённом при настройке ключей. Окно сверяет номер, имя и тип и помечает значение как взятое из файла. |
| **Ключи Universal (.dec)…** | Откройте таблицу DEC или начните с новой, выберите позицию, тип и имя. Введите HEX или нажмите **Сгенерировать**, затем **Сохранить копию DEC…**. Значения скрыты до явного показа. |
| **Ключи Basic и Enhanced (.rdt)…** | Выберите свой RDT, таблицу и позицию. Штатной настройке CPS 2.42 соответствуют 16 позиций Basic и 8 позиций Enhanced по 128 бит. Для конфигурации CPS с `specialprivacy=1` доступна раскладка 4 × 256 бит. |
| **Сервисная калибровка…** | Откройте .test или начните профиль вручную. Выберите сторону A/B, строку и точку, затем сохраните JSON или новую копию .test. Частоты вводятся в МГц, коэффициенты — целыми кодами CPS. Поля BER предназначены для результатов, полученных на внешнем приборе. |

Чтобы пересобрать и запустить приложение, в папке проекта выполните:

```sh
bash macos/build-app.sh
open "dist/TYT Reader.app"
```

Сборка требует инструменты разработчика Apple, `pkg-config` и `libusb`. Приложение включает `libusb`, библиотеку PyYAML с её лицензией MIT и использует установленный на Mac Python 3.8 или новее. Архитектура берётся с Mac, на котором выполнена сборка, а минимальная версия macOS зависит от включённой библиотеки.

## Чтение из Терминала

Прототип считывает через `libusb` DMR ID, каналы, контакты, зоны A/B, группы приёма и списки сканирования. Результат сохраняется в новый JSON с правами `0600`. Формат предназначен для просмотра и сравнения настроек.

Требуются `clang`, `pkg-config`, `libusb` и Python 3.8 или новее. Подключите одну рацию штатным кабелем и включите обычным способом. В Терминале из папки проекта выполните:

```sh
clang -std=c17 -O2 -Wall -Wextra -Werror $(pkg-config --cflags libusb-1.0) \
  read_usb.c $(pkg-config --libs libusb-1.0) -o read_usb
./read_usb --detect
python3 read_settings.py tyt-settings.json
```

`--detect` выводит идентификатор модели из ответа рации. Он может отличаться от маркировки корпуса: штатные MD‑UV380 и MD‑UV390 используют одну разметку кодплага в qdmr. JSON хранит полученный от рации идентификатор в поле `usb_model`. Индексы каналов и контактов начинаются с 1. Поля `privacy_type_code` и `privacy_index_code` содержат только числовые значения из записи канала.

Программа открывает сеанс штатной прошивки, проверяет модель и USB-описатель, выбирает начальный адрес и считывает заданные диапазоны кодплага. Когда рация возвращает общую страницу Privacy, приложению доступны обе таблицы Basic и Enhanced, все 50 шаблонов сообщений и настройки 32 профилей тревоги. Снимки от предыдущих версий содержат данные, доступные на момент их создания. Если после чтения на экране остался режим программирования, выключите и снова включите рацию обычным способом.

Если `ioreg -p IOUSB` показывает рацию, а `libusb` её не находит в изолированной среде, запустите команду из обычного Терминала на Mac.

Протокол чтения и расположение полей сверены с [qdmr 0.15.1](https://github.com/hmatuschek/qdmr/tree/v0.15.1/lib), обработка состояния DFU после команды — с [библиотекой editcp](https://github.com/dalefarnsworth-dmr/dfu/blob/v1.0.20/dfu.go). USB-описатель обычного режима сопоставлен с [документацией RadioFoundry](https://radiofoundry.org/docs/spec/hardware-mduv380).
